## Not done yet (prioritised)

1. **Run migrations automatically on deploy.** The browser walkthrough found a real failure: the dev
   database was one migration behind, so creating a match returned a 500. CI/CD must run
   `npm run db:migrate` before the new app version starts.
2. **Strict CSP.** Clerk's default CSP currently allows `'unsafe-inline'`, `'unsafe-eval'` and any
   `https:` script, which gives weak XSS protection. Move app routes to a nonce-based
   `strict-dynamic` policy.
3. **Phase 3 AI slice:** pitch calibration UI (4+ points), RF-DETR person detection, ByteTrack
   tracking, team clustering, positional metrics with provenance and quality indicators. Before
   that, build a small manually-reviewed evaluation set from footage we have rights to use.
4. **Retention & deletion:** soft-deleted matches keep their footage. Needed: a purge worker,
   `delete_after` from plan retention, and an S3 lifecycle rule `AbortIncompleteMultipartUpload`
   (1 day) for abandoned uploads.
5. Member invitations, role changes (with Clerk reverification), last-owner protection.
6. Account deletion workflow; Clerk webhook (`user.deleted`) with signature verification.
7. Billing provider adapter + verified, idempotent webhooks (provider undecided).
8. Worker hardening for production: container image (non-root, read-only FS, no inbound network),
   least-privilege DB role, structured JSON logs, metrics.
9. Observability: error tracking (Sentry), request ids in logs, health checks.
10. CI pipeline: run `npm run check` + `pytest` + `npm audit` + `pip-audit` + container scan.

## Known limitations and technical debt

- **"Analysis" currently means validation only.** A succeeded job consumes one monthly analysis.
  That must change, or be clearly communicated, before real users are charged.
- `player` role can read every match in the workspace (no per-team scoping yet).
- Uploads cannot resume after a page reload (needs S3 `ListParts`); retries within a session work.
- Usage periods are UTC calendar months, not billing-cycle anchored.
- Rate limiting is fixed-window per user; no IP-based limits for anonymous traffic yet (Clerk
  handles auth endpoints).
- Dev-only dependency advisories (`npm audit`): ESLint's `braces` chain and an esbuild dev-server
  issue in drizzle-kit. Production dependencies: 0 known vulnerabilities.
- `web/AGENTS.md` is regenerated by `next dev`; keep it committed.
- E2E tests use the dev database and a Clerk test user (`e2e+clerk_test@example.com`), and reset
  that user's monthly usage before each run.
- This PC's clock runs about 9 s behind real time (Clerk logs a clock-skew warning; harmless in
  development). Re-sync Windows time if it grows.
